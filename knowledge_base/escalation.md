# Escalado de incidencias a soporte N2

Recopilar descripción exacta, servicio afectado, inicio aproximado, alcance (una persona, varias o servicio crítico), mensaje de error y comprobaciones realizadas.
Distinguir pasos propuestos y comprobaciones realizadas; no dar por realizado un paso.
No incluir contraseñas, claves de API, tokens o información personal innecesaria.

Escalar si faltan permisos, hay riesgo de pérdida de datos, caída de servicio crítico, afectación a múltiples personas o no existe procedimiento aplicable.
No reiniciar producción, cambiar firewall, permisos o configuración sin validación.
Preparar un resumen para revisión. Un borrador no equivale a un ticket registrado.
